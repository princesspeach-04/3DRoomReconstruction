# Aerosense Pipeline Reference (current)

This replaces earlier notes that had you running COLMAP manually
command-by-command — `run_pipeline.py` now does frame extraction +
COLMAP + gsplat training in one call. Manual commands are only needed if
you're debugging a specific step in isolation.

---

## Package Version Lock — DO NOT upgrade these

| Package | Locked Version | Why |
|---|---|---|
| `torch` | `2.4.0+cu124` | Must match CUDA 12.4 exactly |
| `torchvision` | `0.19.0+cu124` | Must match torch 2.4.0 |
| `numpy` | `<2.0` (use 1.26.4) | numpy 2.x breaks pycolmap and torch |
| `gsplat` | already installed via whl | don't reinstall from source |
| `ultralytics` | current | ignore the torch 2.4.0 warning, it works |
| `open3d` | current | needed for `check.py` and `build_object_meshes.py` |
| CUDA Toolkit | 12.4 | matches torch+cu124 |
| Python | 3.10 | gsplat wheel is compiled for cp310 |

**The one thing that silently breaks everything:** any `pip install`
that doesn't pin torch will pull in a CPU-only build. If CUDA stops
working:
```cmd
pip install torch==2.4.0+cu124 torchvision==0.19.0+cu124 --index-url https://download.pytorch.org/whl/cu124 --force-reinstall
pip install "numpy<2.0" --force-reinstall
```

**Sanity check**, run any time you suspect something broke:
```cmd
python -c "import torch; print('CUDA:', torch.cuda.is_available()); print('torch:', torch.__version__); import numpy; print('numpy:', numpy.__version__)"
```
Expected: `CUDA: True`, `torch: 2.4.0+cu124`, `numpy: 1.26.4`.

## Step 1: Capture footage

**Video is the default now**, not individual photos — `run_pipeline.py`
extracts frames itself and auto-extends coverage by resampling the same
video at different offsets if registration is weak, which a fixed set
of photos can't do.

- Walk slowly, steady pace, lots of overlap between viewpoints
- Sharp focus, minimal motion blur — fast whipping pans hurt COLMAP the most
- Transfer via USB or Google Drive — **not WhatsApp** (its compression
  is aggressive enough to visibly hurt reconstruction quality)
- No manual folder prep needed — `run_pipeline.py` clears/creates
  `images/`, `database.db`, `sparse/`, `output/` itself every run

If you ever fall back to a folder of individual photos instead of a
video, the matcher needs to change: photos don't have guaranteed
sequential order, so `run_pipeline.py`'s `sequential_matcher` (built for
one continuous video walk) is wrong for that case — you'd need
`exhaustive_matcher` instead, same as `add_capture.py` uses
`vocab_tree_matcher` for the same reason (a separate session isn't a
guaranteed continuation of the first).

## Step 2: Run the pipeline
```cmd
cd C:\Users\Arni\UnityProjects
venv\Scripts\activate
python run_pipeline.py --video C:\Users\Arni\UnityProjects\video.mp4 --base-dir C:\Users\Arni\UnityProjects\video_Capture
```

This single command does what used to be four manual steps: frame
extraction → `feature_extractor` → `sequential_matcher` → `mapper` →
auto-extend if under-registered → gsplat training. It prints registered
image count along the way — if `Registered images: Y / total` comes
back with `Y` much lower than total, quality will be poor; auto-extend
tries to fix this automatically before training starts, but if it's
still far short after resampling the whole video, that's a sign to
retake footage rather than push forward.

Output lands at:
```
<base_dir>\output\ply\point_cloud_6999.ply
```

**Every command after this one takes `--base-dir` — always pass the
same value.** Most "file not found" errors partway through the pipeline
trace back to this drifting between commands, not an actual bug.

## Step 3: Compute the normalization transform
```cmd
python compute_transform.py --base-dir C:\Users\Arni\UnityProjects\video_Capture
```
Required before anything below this. gsplat silently recenters/rescales/
rotates the scene during training — this recovers that exact transform
so raw COLMAP camera poses can be moved into the trained `.ply`'s
coordinate space. Skipping this is the single most common cause of
objects appearing in the wrong place.

---

## Step 4: YOLO segmentation
```cmd
python run_yolo_segmentation.py --base-dir C:\Users\Arni\UnityProjects\video_Capture --classes chair
```
Produces pixel-level instance masks (not boxes) — this is what lets
`build_object_meshes.py` produce a real chair-shaped mesh instead of a
rectangular blob.

---

## Step 5 (optional but recommended): tune clustering
```cmd
python check.py --base-dir C:\Users\Arni\UnityProjects\video_Capture --max-steps 7000
```
Sweeps DBSCAN `eps` values on the trained point cloud so you can pick a
sensible `--dbscan-eps` for Step 6 without repeatedly re-running the
full mesh build just to tune one number.

---

## Step 6: Build per-object meshes
```cmd
python build_object_meshes.py --base-dir C:\Users\Arni\UnityProjects\video_Capture --max-steps 7000 --dbscan-eps 0.05
```
Votes splat points against the segmentation masks across frames, splits
them into individual chairs via DBSCAN, and reconstructs an actual
surface mesh per chair with Open3D. Writes:
```
<base_dir>\segmentation\objects_3d.json
<base_dir>\output\meshes\chair_0.obj, chair_1.obj, ...
```

If results look off: too few/fragmented chairs → lower
`--min-frame-votes`; holey meshes → lower `--alpha`; chairs merging into
one cluster → lower `--dbscan-eps`.

## Step 7: Unity

1. Open the **GaussianExample** project.
2. **Tools → Gaussian Splats → Create GaussianSplatAsset**, point Input
   PLY at `point_cloud_6999.ply`, Output Folder `Assets/SplatAssets`,
   Create Asset.
3. Select **GaussianSplats** in Hierarchy → assign the new asset.
4. On **Main Camera**: `Fly Camera`'s `Splat Transform` → drag
   `GaussianSplats` in. `Selection Raycaster`'s `Selectable Layer` →
   confirm "Selectable" is User Layer 6 in Project Settings (must match
   the layer `SceneObjectSpawner.cs` hardcodes when spawning objects).
5. On **ObjectSpawner**: `Splat Transform` → `GaussianSplats`.
   `Json Path` → this capture's `segmentation\objects_3d.json`.
   `Min Confidence` → `0` (the mesh pipeline's confidence is a rough
   global average, not a real per-instance score — a strict threshold
   here just silently drops chairs).
6. On **RoomColliderBuilder**: `Splat Transform` → `GaussianSplats`.
7. Press **Play** → right-click to toggle mouse-look + WASD to fly,
   click a chair to select/inspect it, click-drag to reposition it.

## Quick troubleshooting index

| Symptom | Likely cause |
|---|---|
| `CUDA: False` in sanity check | torch got reinstalled CPU-only, see Package Lock fix above |
| Registered images far below total | weak capture (blur/pace), not a script bug — retake |
| Object in wrong place in Unity | `compute_transform.py` wasn't run, or was run before a re-capture |
| `objects_3d.json not found` | `build_object_meshes.py` hasn't run yet, or `--base-dir` mismatch |
| Chairs spawn as boxes not meshes | `mesh_file` path in JSON doesn't resolve — check Console for the fallback warning |
| Nothing spawns despite valid JSON | `Min Confidence` set too high on ObjectSpawner |
| Click-selection does nothing | `Selectable` layer index mismatch, or no `SelectionRaycaster` in scene |
